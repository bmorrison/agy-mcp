#### Required transition table

All transitions and queue/claim/finalization changes use the same assignment mutation lock. Backend terminal evidence is independent of Pi's observation state; keep parent acceptance unrecorded.

| Event / evidence | Dispatch / semantic state | Receipts and lease / allowed next action |
| --- | --- | --- |
| Claim after valid latest completed parent (or fresh assignment) | `claimed` / `running`; latest target reserved | Freeze eligible snapshot; acquire follow-up lease. Reject another claim on the old parent. |
| Proven validation/probe failure before `dispatching` | `terminal` / `failed` | Snapshot becomes not-delivered; release locally owned lease. No automatic retry/resume from an older parent; a new assignment needs an explicit fresh launch. |
| Durable dispatch intent immediately before start | `dispatching` / `running` | Exactly one start attempt; a crash here is ambiguous even if the wire send was not observed. |
| Acknowledged or exact correlated job observed | `acknowledged` / `running` | Snapshot becomes forwarded; retain lease while active. Correlation checks precede accepting a recovered handle. |
| Start timeout/disconnect, incomplete intent record or uncorrelated result | `dispatch_unknown` / `execution_unknown` | Snapshot becomes dispatch-unknown; retain lease; read-only exact-id reconciliation only, never redispatch. Missing record is not non-dispatch evidence. |
| Exact correlated terminal completion plus valid checkpoint/observed conversation | `terminal` / checkpoint-derived semantic state | Persist immutable output, release owned lease; question/progress/blocked permits explicit resume. Final completed permits explicit reopening only, preserving late messages as not-delivered. |
| Backend proved failed/upstream-error/worker-lost, or terminal invalid checkpoint | `terminal` / `failed` | Forwarded stays forwarded; unsnapshotted queued becomes not-delivered; release owned lease. Reject follow-up on this failed turn or stale parent. |
| Cancel signal acknowledged, but no terminal observation | Preserve active/unknown phase and state; save cancel-request evidence | Not proof of cancellation; retain lease, reject new resume; no message consumption claim. |
| Backend proved cancelled | `terminal` / `cancelled` | Preserve forwarded receipts; remaining queued becomes not-delivered; release owned lease; no late resume. |
| Native local stop/short deadline, metadata error or shutdown without terminal evidence | Preserve known dispatch evidence / `execution_unknown` when liveness is unresolved | Preserve receipts, active handles and lease; no upstream-cancel claim. Subsequent exact status may reconcile evidence, but do not rewrite/reanimate Pi lifecycle files. |
| Clean restart after committed completed checkpoint | Retain `terminal` / saved semantic state | Load immutable output/lineage; no inference until explicit valid resume. A foreign live owner or unresolved lock stays observation-only. |

On restart, persisted `dispatching` is treated as dispatch-unknown. A persisted `claimed` record owned by a dead instance fails visibly as admission-abandoned; do not retry it. Atomic write failure cannot enable an unrecorded start. A malformed/unreadable state is a fixed diagnostic, not an excuse to rebuild from MCP history.

## Risks and rollback

- **Native lifecycle mismatch:** external-job follow-up requires completed provider state. Checkpoint semantic state must stay separate and prominent; workflows can otherwise advance on a question. Do not solve this by writing unsupported `waiting` states into Pi status files.
- **Prompt compliance:** AGY can ignore/mangle the checkpoint format. Fail visibly; do not infer a checkpoint from arbitrary prose or auto-spend another inference turn to repair formatting.
- **Owner/server lifetime:** active jobs are server-owned daemon threads. Clean shutdown/reload cancels/interrupts work; crash recovery can observe lost workers but cannot promise continuing active inference. Cross-server cancellation is unsupported. Keep the session/connection alive while the supervisor is merely idle.
- **Local Pi stop gap:** native stop/timeout may end observation while AGY continues. Bound AGY turns independently and provide explicit owning-connection cancel/status. Never make cancellation side effects part of a read-only `status` callback.
- **Retained context/queue privacy:** private state includes supervisor message bodies/cwd and AGY checkpoints. Enforce bounds/permissions, avoid raw task/env duplication and error echoes, and do not include state in package/Python artifacts. Private state is not protection against arbitrary same-user code.
- **Safety ceiling:** a read-only-intent profile and upstream sandbox do not make native Pi tool ceilings enforceable inside AGY. Preserve denials and disclose the boundary. Writer support needs a separate reviewed design.
- **Version/package isolation:** lock/test the inspected public provider/follow-up seam and the corrected owner artifact, not merely its version label; import public subpaths only. Duplicate owner extensions, unsupported hosts, capability ceilings or missing packages fail explicitly; no external-CLI fallback.
- **Dispatch/recovery races:** truncated deterministic ids are checked against full immutable claims; redaction-safe markers permit observation, not guaranteed exactly-once inference. Persist dispatch intent before sending. Ambiguous starts never retry. Automatic stale lock takeover is deliberately unsupported; maintenance needs separate authorization and positive owner/upstream evidence.
- **Deadline composition:** the adapter cannot read a native caller's deadline from provider input. Own bounded admission/metadata scopes and AGY <=300-second execution under a 600-second profile default; document shorter overrides and scheduling delays. The 120-second owner bridge limit is non-dispatch only. No timeout/SDK abort constitutes upstream cancellation.

Rollback is confined to disabling/removing the optional Pi package after its active jobs have been cancelled and terminal evidence inspected. Retain private records for diagnosis; do not automatically purge conversations/jobs/worktrees or remove another process's lease. Revert the new integration/Node CI/boundary test and small documentation links if needed; there is no Python production-code migration to undo. Do not uninstall host dependencies, edit credentials/user settings, kill unrelated processes, or archive this plan as rollback automation.
